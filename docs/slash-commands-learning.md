# Claude Code スラッシュコマンドを「使って覚える」ハンズオン

このドキュメントは、`/` で始まる **スラッシュコマンド** の使い方を、
座学ではなく **実際にこの payment-planner プロジェクトで手を動かして** 覚えるための教材です。

このリポジトリには、学習用のカスタムコマンドが `.claude/commands/` に
4 本（やさしい順）入っています。下のハンズオンに沿って順番に打っていけば、
スラッシュコマンドの仕組みが一通りわかるようになっています。

---

## 1. スラッシュコマンドとは

チャット入力欄で `/` から始めて打つ命令のことです。2 種類あります。

| 種類 | 例 | だれが作る |
|------|----|-----------|
| **組み込みコマンド** | `/help`, `/clear`, `/init`, `/review` | Claude Code に最初から付いている |
| **カスタムコマンド** | `/explain-app`（このrepo独自） | **自分で作る**（このガイドの主役） |

カスタムコマンドの実体は **Markdown ファイル 1 つ**です。置き場所で範囲が変わります。

| 置き場所 | 範囲 | 用途 |
|----------|------|------|
| `.claude/commands/`（プロジェクト内） | この repo を開いた人みんな | チームで共有したいコマンド。git に commit できる |
| `~/.claude/commands/`（ホーム） | 自分の全プロジェクト | 個人的に常用するコマンド |

> このガイドのコマンドはすべて **プロジェクト内** (`.claude/commands/`) にあります。
> だから git に入れて共有できます。

---

## 2. カスタムコマンドの作り方（基本ルール）

**ファイル名 = コマンド名** です。`.claude/commands/review-py.md` を作ると
`/review-py` というコマンドになります。

ファイルの中身は次の形です。

```markdown
---
description: コマンドの一覧に出る説明文
argument-hint: "[引数の入力ヒント]"
allowed-tools: Bash(git status:*)
---

ここから下が「Claude に渡される指示文（プロンプト）」です。
```

### 先頭の `---` で囲んだ部分（frontmatter）

| 項目 | 役割 |
|------|------|
| `description` | `/` を打ったときの一覧やヘルプに出る説明 |
| `argument-hint` | 引数の入力例を表示してくれる |
| `allowed-tools` | 本文で `!` を使ってコマンド実行するとき、事前に許可するツール |
| `model` | 使うモデルを指定（任意） |

### 本文で使える特別な記法

| 記法 | 意味 | 例 |
|------|------|----|
| `$ARGUMENTS` | コマンドの後ろに付けた **引数全体** が入る | `/review-py fetch_data` → `$ARGUMENTS` が `fetch_data` |
| `$1` `$2` | **1個目・2個目** の引数が個別に入る | `/foo a b` → `$1`=a, `$2`=b |
| `` !`コマンド` `` | そのシェルコマンドを**実行した結果**を本文に埋め込む（要 `allowed-tools`） | `` !`git status` `` |
| `@ファイルパス` | そのファイルの**中身**を読み込んで渡す | `@payment_planner.py` |

## 3. ハンズオン（本命）

`.claude/commands/` の 4 本を、やさしい順に実際に打っていきます。
**「打つ → 出力を見る → コマンドのファイルを開いて仕組みを確認 → 改造してみる」**
の流れで進めてください。

### Lv1. `/explain-app` — いちばん簡単なコマンド

引数なし・固定の指示だけのコマンドです。

1. チャットで `/explain-app` と打つ。
2. このアプリ（payment_planner.py）の説明が日本語で返ってくるのを確認。
3. ファイル [`.claude/commands/explain-app.md`](../.claude/commands/explain-app.md) を開く。
   - frontmatter は `description` だけ。
   - 本文がそのまま Claude への指示になっていることを確認。

> **観察ポイント**: 「コマンド = ただの Markdown ファイル」だと体感する。
>
> **次に試す改造**: 本文の「初心者向けに」を「エンジニア向けに技術用語OKで」に
> 書き換えて、もう一度 `/explain-app` を打つ。出力の口調が変わる。

### Lv2. `/review-py` — 引数 `$ARGUMENTS` を使う

コマンドの後ろに付けた言葉を受け取れます。

1. まず引数なしで `/review-py` と打つ → ファイル全体がレビューされる。
2. 次に `/review-py fetch_data` と打つ → `fetch_data` 関数に絞ってレビューされる。
3. `/review-py 例外処理` のように観点を渡してもOK。
4. ファイル [`.claude/commands/review-py.md`](../.claude/commands/review-py.md) を開き、
   本文の `**$ARGUMENTS**` の位置に、自分が打った言葉が入ることを確認。

> **観察ポイント**: `argument-hint` のおかげで `/review-py` を選ぶと
> `[関数名や観点 ...]` という入力例が出る。
>
> **次に試す改造**: レビュー観点に「セキュリティ」を1行追加してみる。

### Lv3. `/safety-check` — `!` でコマンド実行 + `@` でファイル参照

シェルコマンドの実行結果と、ファイルの中身を、両方プロンプトに取り込みます。

1. `/safety-check` と打つ。
2. 最初に `python3 -m py_compile ...` の**構文チェック結果**が表示され、
   そのうえでコードの点検結果（優先度つき）が返ってくるのを確認。
3. ファイル [`.claude/commands/safety-check.md`](../.claude/commands/safety-check.md) を開く。
   - `` !`python3 -m py_compile payment_planner.py ...` `` … これが実際に実行される。
   - `@payment_planner.py` … ファイルの中身が読み込まれる。
   - frontmatter の `allowed-tools` に、実行を許可するコマンドが書いてある
     （ここが無いと `!` の実行がブロックされる）。

> **観察ポイント**: `!` は「Claude が考える」前にシェルが動いて、その**結果の文字列**が
> 指示文に差し込まれる。`@` はファイルを読ませる。
>
> **次に試す改造**: `` !`wc -l payment_planner.py` `` の行を足して、
> 行数も点検材料に含めてみる（`allowed-tools` に `Bash(wc:*)` の追加が必要）。

### Lv4. `/commit-jp` — 全部の合わせ技

`!` を複数使い、`$ARGUMENTS` も使う実用コマンドです。

1. 何かファイルを編集して `git add` し、変更をステージする。
2. `/commit-jp` と打つ → ステージ済みの差分から、日本語のコミットメッセージ案が
   2〜3 パターン返ってくる。
3. `/commit-jp バグ修正の背景も入れて` のように補足を渡すと、それを踏まえた案になる。
4. ファイル [`.claude/commands/commit-jp.md`](../.claude/commands/commit-jp.md) を開き、
   `` !`git status --short` `` と `` !`git diff --staged` `` の2つが
   実行されていること、`$ARGUMENTS` が補足として使われていることを確認。

> **観察ポイント**: frontmatter・`!`（複数）・`$ARGUMENTS` を組み合わせると、
> ここまで実用的なコマンドが作れる。
>
> **注意**: このコマンドは**提案だけ**で、実際の `git commit` はしません。

## 4. 自分でコマンドを 1 本作ってみる（卒業課題）

仕組みがわかったら、自分で新しいコマンドを作ってみましょう。
おすすめは **`/run-app`**（このアプリの起動方法を案内するコマンド）です。

1. `.claude/commands/run-app.md` というファイルを新規作成する。
2. 次をひな形にして書く:

   ```markdown
   ---
   description: payment_planner.py の起動方法を案内する
   ---

   このプロジェクトのアプリの起動方法を、初心者向けに日本語で手順化してください。
   次の情報を踏まえてください:

   - 依存パッケージは requirements.txt（flet, requests）
   - 環境変数 GAS_URL に GAS の WebApp URL を設定する必要がある
   - ローカル起動は `python payment_planner.py`
   - Dockerfile もあるので、Docker での起動方法も併記する
   ```

3. 保存したら `/run-app` と打って動作確認する。
4. 慣れてきたら `argument-hint` で「ローカル / Docker」を選べるようにするなど、
   Lv2〜Lv4 で学んだ記法を足してみる。

## 5. 困ったとき（チェックリスト）

| 症状 | 確認すること |
|------|-------------|
| `/` を打ってもコマンドが出てこない | ファイルが `.claude/commands/` にあるか／拡張子が `.md` か／ファイル名にスペースが無いか |
| `!` のコマンドが実行されない | frontmatter の `allowed-tools` に、そのコマンドを許可しているか |
| `$ARGUMENTS` が空のまま | コマンドの後ろに引数を付けて打ったか（例: `/review-py fetch_data`） |
| `@ファイル` が読まれない | パスが正しいか（プロジェクトルートからの相対パス） |
| frontmatter が効かない | 先頭が `---` で始まり `---` で閉じているか、YAML がずれていないか |

---

## まとめ

- カスタムコマンド = `.claude/commands/` 配下の Markdown ファイル 1 つ。
- frontmatter（`description` / `argument-hint` / `allowed-tools`）で挙動を決める。
- 本文では `$ARGUMENTS`・`` !`コマンド` ``・`@ファイル` が使える。
- まずは付属の 4 本を Lv1→Lv4 で打って体感し、最後に自分で 1 本作る。

楽しみながら、自分専用のコマンドを増やしていってください。
